SQUIRE SQUIRE

Suits you up for the Citadel.

A squire carries the kit, readies the armour and gets the knight on the field. SQUIRE packs your app's Citadel deploy scripts, inspects them against the S-rules, and runs your app at home on the same image, proxy and MySQL that Citadel uses.

$ composer require waynestate/squire --dev

vendor/bin/squire init

The packing list for deploy day

One command packs the files Citadel needs, from templates, for raw PHP or Laravel. Each one is checked off in .squire.json with a SHA-256, and nothing you edited is ever repacked unless you say --force.

  1. build.sh Citadel's build hook. System packages only, POSIX sh, no Composer or npm (S1). Packed
  2. deployments/001-first-release.sh Runs once per app and calls the release with the smoke test off; Apache is not up yet. Packed
  3. scripts/release.sh The idempotent release: install from the lock file, audit, build, migrate, PROCTOR as a report, smoke-test /up. Also your Quick Update post-script. Packed
  4. health.php Citadel's health check: one request to /up, never boots the framework. Packed
  5. The parity kit 11 files docker-compose.squire.yml, .squire/, .env.squire.example, scripts/parity.sh and scripts/parity.ps1: Citadel, on your machine. Packed

vendor/bin/squire doctor

The squire inspects the armour

Doctor reads your repository and checks the rules a machine can decide. It never runs your app and never touches a server. A fail exits 1; a warn or info doesn't. It is a lint, not a gate: wire it into CI if you want it to block.

fail exits 1 warn reported info noted

  • S1build.sh runs no Composer or npm.
  • S3Every script has set -e.
  • S4No download piped into a shell.
  • S8No CRLF in shell scripts.
  • S9Build, first release and release are three jobs.
  • S12Install from the lock file; never update.
  • S13composer.lock is committed.
  • S14The release runs composer audit.
  • S15auth.json stays out of git.
  • S16Laravel runs optimize.
  • S17Migrations run and stay old-code friendly.
  • S18No JSON columns on MySQL 5.6.
  • S19Refuses to run as root.
  • S20PROCTOR is a report, never a bare command.
  • S21The release requests /up at the end.
  • S22One marker per step.
  • S35Locally, the Citadel PHP image.
  • S36A forwarding proxy in front.
  • S37Locally, MySQL 5.6.
  • S41The Docker socket is not mounted.
  • S42.env files stay out of git.
  • S55The health check never boots the framework.
  • S57npm installs with --ignore-scripts.

Every rule, its level and why it matters: BEST_PRACTICES.md. Drift from the templates is a warning under S9, never a failure; your copies are yours to edit.

Commands

  • down

pin prints the digests of the images you pulled, so you can pin them. reset also removes the volumes.

Containers drop capabilities, set no-new-privileges and carry memory and process limits; the database listens on loopback only. The compose file refuses to start without real passwords.

No access to the real image? --fallback builds an approximation from the official PHP image plus Citadel's extensions. Good for a practice bout, not for proving parity.

Citadel setup

Onto the field

What lands on Citadel is the scripts SQUIRE packed; the package itself stays on your machine and in CI.

  1. 1

    Point the dashboard at the kit

    Build script build.sh, health check ["php","health.php"], Quick Update post-script ./scripts/release.sh as user citadel.

  2. 2

    Commit the lock files

    composer.lock, and package-lock.json or pnpm-lock.yaml if you have a frontend. The lock file is the release contract.

  3. 3

    Mark the scripts executable

    Git on Windows forgets: git update-index --chmod=+x build.sh scripts/*.sh deployments/*.sh

  4. 4

    Settings in the dashboard

    Set SQUIRE_* values in the dashboard environment, never in a file in the repository. All of them are optional.

Known limits in 0.1

Scuffs on the leather

SQUIRE 0.1 is unreleased, and honest about where it guessed. The full list, with the default each guess chose, is OPEN_QUESTIONS.md.

  • The local php.ini is an approximation of Citadel's. For exact parity, copy theirs in.
  • The Citadel image has no registry digest to pin yet; doctor warns under S67 until you run pin.
  • A full Update may not refresh vendor/. Use scripts/release.sh as the Quick Update post-script too.
  • PROCTOR can report during a release, but cannot act as a deploy gate yet.
